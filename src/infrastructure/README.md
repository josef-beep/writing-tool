Infrastructure owns catalog/lease storage, confined managed-file publication, coordinated workspace changes, settings, immutable revisions, complete archives, recovery proposals and exports. Payload JSON/WRT files remain authoritative; catalogs retain identities, relative paths, relationships and durable operation evidence.

Linux managed I/O uses directory descriptors. macOS/Windows dispatch through the trusted [native adapter](../../native/confined-fs/README.md). Its binary location is configured by main and passed to the utility host before storage initialization. Windows directory synchronization requires local NTFS and a successful pinned-object native metadata/storage flush; unavailable capabilities fail before mutation. Native source is uncompiled and unverified in this coding pass. SQLite VFS path handling remains a separate verification gate.


Export conversion consumes a private, durable capture keyed by the original operation ID. `export-captures.ts` stores compact manifests and shared immutable payloads under user-data, pinning the saved manuscript/formatting, chapter order/calendar and catalog generation without adding user-visible revisions. `captured-state.ts` shares logical closure validation with revisions and archive recovery. Cache creation/reclamation uses the coordinator's cross-host gate. Terminal job evidence precedes reclamation; unresolved exports retain their pins. Completed output jobs keep the original publication digest, checked again before native acknowledgement/open registration. All of this source remains unverified; PDF validation currently checks structural completion, with rendered text/format fidelity left to release verification.
