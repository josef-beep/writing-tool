# Story 1.1 local implementation evidence

Verified 2026-10-17 on Zorin OS 18.1 (Ubuntu-family Linux x64), graphical session `DISPLAY=:1`. Source provenance is the successfully installed official scaffold at `/tmp/writingtool-starter.461RNV/writingtool`, generated by create-electron-app/Forge 8.0.1 using `--template webpack --typescript`. Root configs were imported and adapted; existing planning, solution and IDE files were preserved. VCS remains unavailable; the story's baseline is `NO_VCS`.

## Delivered boundary

React shell with adopted Preview gray Dark surfaces and textual checking/ready/unavailable status. The only public preload method is `window.writingTool.readiness()`. It creates its own canonical UUID and sends a closed protocol-1 query. Main checks owned webContents, main frame and exact local URL, validates before dispatch, then routes to a separately bundled live Electron utility process. Application code performs the non-mutating query without Electron, UI, filesystem or persistence imports. Main validates results/correlation and preload validates them again. Five-second timeout, 32-request bound, duplicate-ID protection and reply/failure/destruction/shutdown cleanup are implemented. Subsequent checks invalidate ready after host exit.

Sandbox/context isolation are required by preload at runtime, and main disables Node integration/webviews, denies permissions, navigation/redirects and new windows. The development server binds loopback; external source maps and disabled HMR client retain the same strict HTML CSP in development. No writing store, editor, database, recovery or installer behavior is claimed.

## Actual commands and results

- `ELECTRON_CACHE=/tmp/writingtool-electron-cache npm ci --cache=/tmp/writingtool-npm-cache`: passed a clean install; root postinstall downloaded/selected the official Electron runtime. The explicit cache locations accommodated this environment's restricted home-cache writes. Normal documented command is `npm ci`.
- `npm run typecheck`: passed with strict TypeScript checks.
- `npm test`: all eleven meaningful protocol, application-query, correlation, transport failure/timeout/bounds/cleanup, sender-security and inner-layer dependency tests passed; four smoke-runner regression tests also passed.
- `npm run lint`: passed (`oxlint --deny-warnings src tests scripts`).
- `npm run smoke`: seven real development-launch scenarios passed. Requires local TCP/display access outside the execution sandbox in this environment.
- `npm run package`: passed, creating `out/WritingTool-linux-x64/WritingTool` with ASAR-contained main/preload/renderer/utility bundles and enabled production security fuses.
- `npm run smoke:packaged`: seven real packaged-launch scenarios passed. The runner launches the bundled executable directly with `PATH` containing only its own directory; the application/utility do not require a separate Node executable.
- `npm audit --json`: exit 1, eight development-tool findings (six high, two moderate, zero critical); retained as a known limitation.
- `npm audit --omit=dev --json`: passed, zero production dependency findings. This is registry advisory evidence, not a claim of comprehensive application security.

Each smoke suite verifies live ready, host-start failure (`HOST_START_FAILED`), immediate host exit (`HOST_EXITED`), invalid host result (`INVALID_RESPONSE`), host silence (`TIMEOUT`), initial ready followed by host exit, and the handled utility FatalError event path (diagnostic event injection, not a real OOM/crash). In every case it additionally sends malformed IPC from the real preload and checks rejection; opens a separate sandboxed window with the same preload and verifies its sender is denied; attempts external navigation/window creation; checks that the public bridge contains only `readiness` and renderer Node globals are absent; asserts the pending map is empty; and exercises live geolocation permission query/request denial handlers. A valid rendered state also proves the preload's runtime sandbox/context-isolation assertion passed. Profiles are temporary and removed after process-tree shutdown/stream closure; cleanup failure retains the profile. Targeted tests also cover timeout/late valid reply recovery, first terminal cause preservation, throwing transports, output draining/parsing and stubborn descendant termination. The runner uses the native Node/Forge JS entry and correct macOS bundle path; actual Windows/macOS launches remain unverified.

Raw check/install/package outputs, exact top-level versions, registry audit reports and JSON lines emitted by actual Electron runs are in [story-1-1-evidence](story-1-1-evidence/). Development and package builds must run sequentially because Forge shares `.webpack`; an initial overlapping attempt was discarded and rerun sequentially. The first development check also caught the template's eval-source-map conflict with strict CSP; external source maps fixed it without relaxing script policy.
