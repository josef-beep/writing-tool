# Universe folder and profile persistence

Engineering detail adopted under the standing execution approval. This specializes the data/publication/coordination foundations for Story1.2 only. It is a contract, not runtime proof or closure of full technical/platform gates.

## Files and schema

Registry: `writingtool.json` is the root discovery descriptor; `profiles/<universe-id>.json` owns the profile; `images/` is the managed asset root; `database/catalog.sqlite`, `database/lease.sqlite`, `database/operations/<operation-id>/` hold catalog, ownership and publication evidence. Do not add future entity/category tables. A root selected by a native directory chooser must be an existing directory. Reject symlink/reparse-point managed paths, resolved escapes and aliased hard-linked managed files. Resolve root aliases to one physical root; reject a copied UUID root while its recorded original still exists at a different physical root. Moving the entire root does not change identity.

Root descriptor is closed: `{schemaVersion:1,kind:"universe",id:UUID,rootId:UUID,creationOperationId:UUID}`. IDs must match catalog and JSON. Profile is the closed foundation envelope with schemaVersion1, recordType `universe-profile`, id=owner.id=universeId, owner.kind `universe`, recordVersion UUID, data `{name:string,description:string}`. Name must contain non-whitespace and is stored with surrounding whitespace trimmed; description defaults to empty and is otherwise preserved. No arbitrary length limit. Reject malformed UTF-8, BOM, duplicate JSON keys and unpaired surrogates. JSON is UTF-8 with LF; serialize deterministically. Unknown fields/versions are not writable. Domain values need semantic identity/hash validation in addition to structural schemas.

The initial catalog uses application_id `1465140300` and user_version1. Read/validate supported identity/version before writable open; no migration is implicitly applied. Version1 is initial creation only. Unsupported or missing catalog/lease/descriptor never triggers automatic schema initialization. SQLite built-in `node:sqlite` in pinned Electron44.9.0 is selected behind an application port (utility-process probe in implementation-artifacts/sqlite-runtime-probe.md). Use rollback journal DELETE with synchronous EXTRA, foreign_keys ON and zero busy timeout; verify settings and engine on actual adapter/package. Lease connection holds BEGIN EXCLUSIVE until drained close; do not commit its ownership transaction. Keep SQL out of domain/application/presentation.

Required catalog tables (exact DDL accompanies implementation before first writes):

- `unit_meta`: singleton supported schema/owner/root identity, exact TEXT content generation, operational session token, creation operation/digest and creation state `preparing|complete`.
- `root_locations`: one root ID, owner identity, absolute base path and UUID binding version. This separate row owns location; profile/object rows have no absolute paths.
- `records`: ID/root ID/type/relative path/version/SHA-256; profile payload remains JSON.
- `committed_operations`: operation UUID primary key, semantic request digest, exact TEXT generation, result digest and serialized closed receipt. Retain durable receipts; no arbitrary cleanup retirement.

The dedicated lease database has one `lease_identity` row with universe/root IDs and supported version. Verify that row while holding the lock. Validate connection transaction state and descriptor/physical-root identity before each publication and within catalog expectation checks. On new ownership recover old journals before minting/storing a fresh session UUID. Lost lock/identity/fence blocks mutations. There is no heartbeat stealing. Single-root candidate activation is nonblocking and changes the active context only after validation; no cross-root mutation or aggregate receipt is introduced here. Preserve the old active context if a candidate fails.

## Creation and activation

Reject a nonempty root before creation. Exclusively reserve a closed `.writingtool-creation.json` bootstrap record containing schemaVersion, operationId, ownerId, rootId, requestDigest and intended profile envelope. Flush it and the parent directory before creating managed paths. Use exclusive creation for every new managed file/directory; never replace unrelated paths. Initialize lease/catalog, acquire ownership, write/flush profile and discovery descriptor and verify all hashes/identities. Commit generation `1`, profile row, complete creation state and durable creation receipt in one catalog transaction; flush containing directory entries. A normal open requires the matching complete catalog decision and valid files, not just existence of a marker/database. Failure preserves partial evidence; a new unrelated creation never reuses that folder. A partial creation is either validated as committed and finalized on open or refused as recovery-required; do not guess an unfinished creation into a new authority or recursively delete its root. A bootstrap reservation may remain as evidence after successful creation; it never outranks the catalog decision or later generations.

Only expose the new active universe after complete verification. Cancellation of either form/chooser changes no authority. Native selection is owned by main: renderer methods accept profile/identity/version/revision fields, never path strings. Main privately forwards the chooser result to the utility. Opening an existing root must not copy its live catalog into application/project storage.

## Profile save and reconciliation

Serialize all unit requests/publication in the authoritative host. Readiness remains separate and non-mutating. Save input contains operationId, ownerId, expectedUnitGeneration, expectedRecordVersion, submittedEditorRevision and closed profile data. Hash RFC8785 canonical JSON of the foundation semantic request fields (including command `universe.profile.save`); exclude transport/operation IDs. No floating-point domain values enter this slice. Same operation/digest returns the retained receipt; differing digest is rejected. Receipt is the closed foundation saveReceipt.

Before changing profile bytes, durably stage a closed journal: schemaVersion1, scope `single-unit`, command, owner/root/operation IDs, semantic request/digest, expected/target generation, fencing token, before/after envelope bytes, their hashes/lengths and typed profile catalog before/after metadata. Include the expected record version. The only live payload target is the derived `profiles/<owner-id>.json`; never execute journal SQL or accept journal-selected arbitrary paths. Journal/staging files must be valid supported confined regular files before replay.

Publish profile replacement on the same filesystem, flush file/directory, then commit catalog version/hash/generation and operation receipt transactionally with expected generation/fence/version checks. Verify committed bytes/receipt and durably finalize before releasing the gate or admitting another mutation. File/flush failure is an error, never permission to weaken durability. Unknown commit outcome requires querying durable decision evidence. Once committed, failure to finalize requires redo, not undo.

On reopen recover SQLite, lock ownership and examine every operation workspace before profile validation/activation. Definitively uncommitted expected generation: undo to verified before bytes; committed target generation: verify/finish after bytes and finalize. Unexpected live bytes, missing/corrupt staging, unsupported plan, conflicting identities or unexplained generation block writes/activation and preserve evidence. Interrupted undo/redo is repeatable. A finalized operation at a valid later generation is cleanup-only: never restore its old after image. Retain finalized receipts; keeping staging is acceptable until explicit cleanup is delivered. On retry return the original receipt even if newer generations exist, without falsely describing it as the current profile.

## Relocation, transport and shutdown

On selected-root open, compare physical identity with the stored binding. Reject a copied root if its original still exists elsewhere. After ownership/recovery and complete identity verification, update only root_locations.basePath/bindingVersion by compare-and-swap in a catalog transaction. Content generation, object paths/rows, profile bytes and permanent IDs remain unchanged. A crash before/after this transaction leaves a valid old/new binding; next selected open repeats validation. Do not move directories on the user's behalf.

Publish closed command-specific runtime types/validators before routing: create/open/current/profile-save/close; external create/open trigger main's native picker, internal host requests carry privately resolved basePath. All messages carry protocolVersion1, canonical requestId and exact command, with no unknown keys. Success is a command-correlated snapshot/receipt, canceled is an explicit nonmutating result, error uses the foundation outcome/retry model plus command-specific stable codes. Snapshots expose only owner/root identity, profile/version/generation and displayed location; never SQLite handles/SQL. Preserve exact trusted sender/main-frame/URL checks. Bound host pending requests; validate replies against their command and correlation. Late valid replies do not poison the connection.

A mutation timeout/host loss is outcome unknown. Retain operation ID and submitted payload, prevent blind reissue with a new operation and prevent navigation discard until reopening/reconciliation determines outcome. An explicit reconnect/reopen may restart a definitely exited host and recover durable evidence; no simultaneous replacement authority. Errors must not report not-committed unless established. Current/open after recovery returns the actually validated current profile; historical receipt is separate. Keep readiness timeout codes unchanged.

For close/switch, reject new mutation admission, drain queued publication, close catalogs, roll back/close ownership connections, then acknowledge host shutdown. Main must not kill the host merely because the renderer window closed. Drain failure keeps normal close pending and reports failure; forced termination is crash recovery, never a successful normal close. Full revision/backup close obligations arrive in Epic5 and are not claimed by this slice.

## Version-one implementation formats

Closed JSON schemas are published as `schemas/universe-{profile,descriptor,bootstrap,journal,transport}.schema.json`; the foundation `saveReceipt` is reused unchanged. Runtime validation additionally enforces name trimming, owner identity, target-generation arithmetic, byte digests, derived profile paths and request/receipt agreement. `src/infrastructure/universe-ddl.ts` publishes the exact initial catalog/lease DDL before any adapter creation. A save journal embeds complete UTF-8 before/after byte strings plus decimal byte lengths and hashes, typed record metadata, semantic request and receipt. Finalization/abort markers are closed `{schemaVersion:1,operationId,requestDigest}`. Missing/corrupt evidence blocks activation. No migration exists: schema version one is created only in an empty root reserved by the exclusive bootstrap file.

An explicit reconciliation reopen uses closed `universe.open` with optional `reconcileOperationId` (UUID); main pins unresolved operations to the original privately selected folder. Its success contains the actually verified current snapshot and closed `reconciliation:{operationId,outcome:committed|not-committed}`. A committed outcome additionally carries the retained historical foundation receipt correlated to that operation; it does not claim the receipt is the latest profile. Proven absence after complete recovery returns explicit `not-committed` and no receipt. Wrong folder selection preserves the pending outcome. Ordinary open has neither reconciliation metadata nor a receipt. A definitively aborted journal may retry the same immutable plan after fresh ownership checks; only the current operational fence is adopted, without changing its original staged content IDs or receipt.

Review specialization: internal reconciliation requests may carry closed `reconcileExpected` identity plus the original typed mutation. The utility validates descriptor owner/root (or creation operation), original semantic digest and copied-root authority before activation, recovery/rebinding or fencing changes. Public renderer DTOs gain no paths or expected-identity authority. Physical root aliases resolve canonically; an active verified same-inode move releases obsolete SQLite connection names and reacquires/reconciles the same files. Reused former paths permit a demonstrably unrelated directory/owner; uncertain prior authority remains blocked.

Final/abort marker publication stages and flushes a complete temporary marker before atomic rename. Torn legacy metadata is retained under `.damaged-<UUID>` and can be completed from matching valid journal/catalog evidence; valid conflicting identities and missing/corrupt journals still block. Managed JSON I/O uses locally verified Linux directory handles; unsupported platforms fail safely. SQLite's canonicalized native VFS remains a separate, unproven adversarial race boundary despite catalog/lease identity checks. Completed creation receipts survive an activation failure as a known committed outcome; a failure before exclusive creation reservation is known not committed.
