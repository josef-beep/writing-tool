# Project storage and transport

A project root is independent of its universe. It contains `writingtool.json`, `.writingtool-creation.json`, `database/catalog.sqlite`, `database/lease.sqlite`, `images/` and `projects/<project UUID>.json`. Version-one discovery is closed: `{schemaVersion:1,kind:"project",id,rootId,creationOperationId}`. The immutable metadata envelope is `{schemaVersion:1,recordType:"project-metadata",id,owner:{kind:"project",id},universeId,recordVersion,data:{}}`. All identities and versions are canonical UUIDs; no name, story, chapter or volume fields/tables are introduced.

The catalog uses SQLite application ID 1465140301, user version 1, rollback DELETE journals, synchronous EXTRA and foreign keys. Its exact DDL is in `project-storage.ts`: unit_meta, root_locations, records, universe_locations and committed_operations only. The lease has the same format ID/version and a single lease_identity row. Its private connection holds BEGIN EXCLUSIVE throughout ownership. Managed files use the existing no-follow, single-link and directory-flush primitives. Unsupported format headers are rejected before writable connections.

unit_meta holds permanent project/root/universe UUIDs, exact decimal generation, creation operation/digest/state and authority session. root_locations holds one separate project base binding with a UUID comparison token. records holds one metadata path/hash/version. universe_locations holds the associated universe UUID and machine-local resolution with a comparison token; changing this location cannot change the association. Neither binding changes content generation. Copies whose prior bound root still contains authority evidence are rejected. Whole-root relocation validates identity and lease, then compares and swaps only root_locations.

Creation exclusively reserves an empty existing folder with the complete metadata envelope and request digest, durably initializes directories/catalog/lease, writes metadata and discovery, then commits generation 1, complete state and the creation receipt together. Acknowledgment follows full hash/identity/receipt verification and directory flush. No failure removes or overwrites partial evidence. Incomplete creation is conservatively blocked for recovery; it is never automatically recreated. A complete decision with valid discovery can reopen after a lost acknowledgment. No metadata mutation is exposed in this increment.

Protocol 1 exposes only project.create({operationId}), project.open(), project.current() and project.close(), with correlated UUID request IDs and closed results. Main alone adds selected project/universe paths. Results are ok with a project snapshot (including the resolved authoritative universe snapshot), canceled, or the existing closed operation/error shape. Creation returns its durable receipt. Main uses an internal locate outcome to request a native universe folder when saved resolution fails; this outcome never reaches the renderer. Requests/results are validated at both transport boundaries; outstanding requests are bounded and timeout to unknown for creation. Unknown creation blocks further workspace changes and normal shutdown until an explicit reopen of the same creation identity confirms the outcome.

Activation acquires and verifies a candidate project and matching universe before releasing previous context. A currently active matching universe reuses the existing store; candidates never create project-local universe copies. Wrong identity, cancellation, occupied authority or invalid roots release candidates and preserve previous active context. Native location selection resolves a UUID rather than reassigning it. There is no cross-unit content mutation: project creation references an already existing universe and never saves universe content. Base and resolution bindings are operational metadata, validated under their owning leases. Existing unknown universe operations must be reconciled before project transitions. Normal shutdown drains project before universe.

All runtime, interruption, concurrency, relocation, schema, transport and packaged-platform checks are deferred by the explicit coding-first instruction. This document claims no verification evidence.
