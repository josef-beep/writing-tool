# Confined filesystem native source

This is trusted main/utility infrastructure, using stable Node-API v8 and the target OS APIs. It is never a renderer binding or an IPC handle API. `src/infrastructure/confined-fs.ts` loads the module lazily on macOS/Windows and validates its contract version and all required operations. Linux continues using the existing `/proc/self/fd` descriptor-relative implementation without loading this addon. Unknown platforms, architectures, incompatible binaries and missing capabilities fail explicitly, with no path-based fallback.

## Build and resource contract

`binding.gyp` defines `confined_fs`, with `addon.cc` plus exactly one platform source. Build on the matching accepted host with the bundled Electron headers and target architecture; supported targets are darwin-x64, darwin-arm64 and win32-x64. The raw output is `native/confined-fs/build/Release/confined_fs.node`. The release build must copy it to the trusted unpacked resource `native/confined-fs/<platform>-<arch>/confined_fs.node` under Electron's resources directory. The stable ABI avoids direct V8/Electron private APIs, but does not remove per-OS/architecture build requirements. Trusted bootstrap can fix the exact absolute module path with `configureConfinedFs` before constructing the coordinator, including utility-process startup. Development loads only the repository build output; packaged loading never falls back to the current working directory. Users do not compile or install addons. Generated build directories and `.node` binaries are not source artifacts.

The low-level API owns opaque handles, closes them explicitly and also finalizes abandoned handles. Each traversal opens a single relative segment from its pinned predecessor. Native creation invokes the reservation callback synchronously immediately after the exclusive reservation, before postcreation validation, file writes or flushes; callback exceptions preserve the pending JavaScript exception and close the handle. The staging callback remains after completed staging-file and directory flushes. Errors propagate with stable diagnostic `code` strings (`ENOENT`, `EEXIST`, `ENOTSUP`, `EALIAS`, `EIO`, etc.); JavaScript callback exceptions remain unchanged. The coordinator retains responsibility for operation outcome and recovery evidence. No lower-level exception establishes that a mutation did not happen.

## Native operations and limitations

- macOS starts at `/`, opens each directory with `openat`, `O_DIRECTORY` and `O_NOFOLLOW`, rejects nonregular/multiply-linked files and uses descriptor identity checks. `renameatx_np` supplies `RENAME_EXCL` for no-replace publication/preservation; replacement uses the same pinned directory. Removal uses `unlinkat` after identity/content validation. Regular-file flush requires `F_FULLFSYNC`; directory metadata uses `fsync`. Any failure propagates, without a weaker flush fallback.
- Windows opens the drive root, then uses `NtCreateFile` with `RootDirectory`, a one-segment name, `FILE_OPEN_REPARSE_POINT` and synchronous I/O. Every object rejects reparse points; files reject multiple links and non-disk objects. Handle-reported names must match the requested spelling to reject alternate filename aliases. Existing files are opened with delete rights for handle-based rename/removal; inability to obtain those rights is a safe failure. Rename uses `SetFileInformationByHandle(FileRenameInfo)` with the pinned parent as `RootDirectory`, and deletion uses `FileDispositionInfo` on the verified handle. UNC/device roots are explicitly unsupported. Regular files use `FlushFileBuffers`.
- Windows directory synchronization queries the filesystem through the pinned handle and requires NTFS, then uses `ReOpenFile` to obtain write rights on that same object and verifies its identity. `NtFlushBuffersFileEx` with flags **0** requests metadata and underlying-storage synchronization. Both the direct status and synchronous I/O completion status must succeed. This is a source implementation based on the documented native flush contract and MS-FSA directory-stream behavior, **not runtime or physical-durability proof**. The MS-FSA product note explicitly limits directory-structure persistence to NTFS; other filesystems may acknowledge without doing that work, so they are rejected before mutation. Unavailable exports, denied write rights, incompatible handles and failed flushes also fail explicitly. High-level mutation helpers preflight this operation before their first mutation and still synchronize after publication; no file-only or weaker-flags fallback exists. UNC/device roots remain unsupported.
- TS publication retains identity/content preconditions, exclusive temporary staging, no-replace creation and postrename directory synchronization. Sources and destination directories stay pinned while output files stream in 256 KiB chunks. Expected private-output digests are checked before publication. Prepublication failures preserve existing destinations and retain temporary evidence. The file hashing helper also streams through a handle opened under a pinned parent. Managed reads intentionally return the complete caller-requested bytes, as their existing signature requires.
- Native identity checks protect the pinned object and namespace boundaries, but do not establish a transaction against hostile concurrent writers. The owning-unit lease/publication gate remains mandatory, as on Linux. SQLite's own VFS is separate; these sources do not make SQLite descriptor-relative.

## Remaining verification gates

Only source inspection was authorized for this coding pass. No native compilation, test, typecheck, lint, runtime probe, build, packaging or installer execution was performed. Required later checks include compilation with Electron headers for all three native targets; loader paths, code signing and installed unpacked resource availability; native ABI and exception/callback/handle cleanup; directory-retarget, symlink/reparse, case/short-name/hardlink and concurrent identity/content changes; exclusive/no-replace collisions; Unicode/long filenames and denied access; every write/flush/rename/delete interruption; full disks, lost volumes and recovery outcome preservation. macOS filesystem/hardware `F_FULLFSYNC` and directory durability need physical interruption evidence. Windows must verify NtCreateFile/ReOpenFile handle interoperability, actual synchronous NtFlushBuffersFileEx export/ABI/rights/completion behavior on NTFS, rejection of non-NTFS no-op flushes, and its filesystem/hardware interruption matrix. SQLite VFS/lease/catalog durability remains its separate verification gate.

Webpack preserves this adapter’s runtime `createRequire` through a file-specific parser setting; see [Webpack parser documentation](https://webpack.js.org/configuration/module/#moduleparserjavascriptcreaterequire). Forge builds against matching Electron headers and places packaged native binaries outside ASAR. No build hooks have run in this pass.
